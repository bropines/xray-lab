# Xray Lab

**Настоящий Xray-core в браузере.** Проверьте конфиг сразу на нескольких версиях ядра, поработайте с командной строкой `xray` в терминале, сделайте ключи и сертификаты — всё на вашем устройстве, ничего не отправляется.

**Сайт:** https://bropines.github.io/xray-lab/ · [English](README.md)

Движок — [xray-wasm](https://github.com/bropines/xray-wasm): исходники Xray-core без изменений, скомпилированные в WebAssembly для каждого релиза. Если страница говорит, что конфиг загружается, его загрузил официальный бинарник этого релиза.

## Что умеет

### Проверка
Вставьте, откройте или перетащите конфиг, выберите версии ядра, нажмите **Проверить**.

- Каждая версия отвечает так же, как `xray run -test` на сервере: **Загружается**, **Отклонён** (с сообщением самого ядра, его можно скопировать), **Не определено** (ядро остановилось, не найдя файл, которого у страницы не было, — приложите или скачайте его и проверьте снова), **Падение**, **Нет ответа**, **Недоступно**.
- Версии сгруппированы: стабильные / пре-релизы / отозванные, новые сверху, есть поиск. По умолчанию выбраны самая новая стабильная, v26.7.28 (на ней работают ноды Remnawave) и v26.3.27 (самая старая сборка). «Все стабильные» и «Все» заранее говорят, сколько мегабайт придётся скачать; версии проверяются по одной, с прогрессом, и проверку можно остановить.
- Комментарии и лишние запятые убираются до того, как конфиг попадёт в ядро (страница пишет, что убрала; номера строк не сдвигаются).
- `geoip.dat` / `geosite.dat`: загрузите свои или скачайте из [Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat) через jsDelivr.
- Редактор подсказывает ключи и значения по JSON Schema выбранной версии ([xray-schema](https://github.com/bropines/xray-schema)).
- **Поделиться** (только по нажатию) сжимает конфиг в часть ссылки после `#` — с предупреждением, что ключи из конфига уйдут вместе со ссылкой.

Чего «Загружается» **не** доказывает: всего, что происходит только при запуске (порты, интерфейсы, DNS, доступность сервера), и проверок, зависящих от ОС, — в браузере ядро работает как `GOOS=js`, поэтому, например, проверки tun-inbound для Linux/Windows пропускаются, и результат об этом говорит.

### Терминал
Оболочка с установленным `xray` (xterm.js). `xray` запускает выбранную версию, `xray@26.7.28 …` — конкретную. История, дополнение по Tab (команды, флаги, файлы, версии), перенаправление `> файл` и встроенные команды: `help ls cat edit rm cp mv cd pwd echo history clear use versions upload download`. Файловая система общая со страницей проверки: `xray run -test -c config.json` запускается на том, что вы вставили. Работает на телефоне — есть экранный ряд с Tab, стрелками и Ctrl+C.

### Инструменты
Формы поверх CLI, каждая показывает точную команду: ключи REALITY (`x25519`), ключи WireGuard (`wg`), UUID (случайный или `uuid -i`), VLESS Encryption (`vlessenc`), ML-DSA-65 / ML-KEM-768, самоподписанные TLS-сертификаты (`tls cert`, файлы можно скачать) и быстрый переход к проверке конфига на всех версиях.

Английский и русский интерфейс, светлая/тёмная/системная тема, управление с клавиатуры, сначала мобильная вёрстка.

## Приватность

Всё работает во вкладке браузера. Нет бэкенда, аналитики и аккаунтов. Страница запрашивает только бинарники ядра (с GitHub Pages проекта xray-wasm), схемы конфига (jsDelivr) и — только если попросите — geo-файлы (jsDelivr / raw.githubusercontent.com). Ни один запрос не содержит вашего конфига.

Небольшие файлы сессии (например, `config.json`) хранятся в localStorage браузера, чтобы пережить перезагрузку; скачанные ядра — в Cache Storage. «О сайте» → «Удалить скачанные ядра» очищает кэш.

## Как это устроено

```
 XTLS/Xray-core (тег релиза)
        │  go build, GOOS=js GOARCH=wasm, исходники без изменений
        ▼
 релиз xray-wasm ── manifest.json, wasm_exec.js, <тег>.xray.wasm.gz (~12 МБ каждый)
        │  раздаётся с bropines.github.io/xray-wasm (CORS: *)
        ▼
 эта страница ── скачивает один раз ─▶ Cache Storage (ключ — sha256)
        │
        ▼
 Web Worker: рантайм Go + xray ◀── конфиг / аргументы CLI + файлы в памяти
        │
        └──▶ вердикт, stdout/stderr, файлы, которые записала команда
```

Все обращения к библиотеке проходят через один модуль, `src/engine/` (типизирован по контракту библиотеки, для тестов есть явно помеченный фальшивый движок). Он добавляет состояние загрузки для каждой версии, выполнение по одному вызову, отмену загрузок и кэш.

## Разработка

Нужен [Bun](https://bun.sh) 1.3.

```sh
bun install
bun run dev          # http://localhost:5199/xray-lab/ — ядра с Pages проекта xray-wasm
bun run dev:fake     # без ядер: фальшивый движок (результаты выдуманы, интерфейс об этом пишет)
bun run dev:local    # ядра из ../xray-wasm/dist-wasm (локальная сборка библиотеки)
```

Чтобы работать с локальной копией самой библиотеки: `bun add ../xray-wasm` (и `bun add <URL тарбола релиза>`, чтобы вернуться).

Проверки — все четыре должны проходить:

```sh
bunx tsc --noEmit
bun run lint
bun test
bun run build && bun run preview   # http://localhost:4199/xray-lab/
```

Переменные сборки:

| Переменная | По умолчанию | Значение |
|---|---|---|
| `VITE_XRAY_WASM_BASE` | `https://bropines.github.io/xray-wasm/` | Папка с `manifest.json` библиотеки (URL или `./путь`). |
| `VITE_FAKE_ENGINE` | не задана | `1` — собрать с фальшивым движком вместо xray-wasm. |

## Публикация

`.github/workflows/pages.yml` запускается на каждый push в `main` (и вручную): установка, проверка типов, линтер, тесты, сборка, публикация на GitHub Pages. В настройках репозитория: **Pages → Source: GitHub Actions**.

Переменные репозитория (необязательно):

- `XRAY_WASM_RELEASE=latest` — собирать с самым новым релизом xray-wasm вместо закреплённого (то же можно выбрать при ручном запуске);
- `XRAY_WASM_BASE` — брать ядра с другого адреса или `self`, чтобы скопировать ядра релиза (`manifest.json`, `wasm_exec.js`, `*.xray.wasm.gz`) в сам сайт, в `./xray-wasm/`.

## Обновление до нового релиза xray-wasm

Одна строка в `package.json`:

```json
"xray-wasm": "https://github.com/bropines/xray-wasm/releases/download/v0.2.0/xray-wasm-0.2.0.tgz"
```

затем `bun install`, проверки, коммит. Для новых релизов Xray здесь ничего делать не нужно: список версий берётся из манифеста библиотеки.
